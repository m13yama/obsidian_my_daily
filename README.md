# My Daily

Obsidianで、テンプレートと前回のデイリーノートを組み合わせて今日のノートを作成するプラグインです。

例えば「今日の予定」「日記」はテンプレートから作り、「継続タスク」だけ前回の内容を引き継げます。引き継ぐ見出しを `## @carry 継続タスク` のように書くだけで指定できます。

## インストール

1. Vault内に `.obsidian/plugins/my-daily/` フォルダを作成します。
2. このプロジェクトの `main.js` と `manifest.json` をそのフォルダにコピーします。
3. Obsidianを再起動し、設定 → コミュニティプラグインで **My Daily** を有効にします。
4. [サンプルテンプレート](examples/Daily.md)をVaultの `Templates/Daily.md` にコピーします。
5. 設定 → My Dailyで保存先、テンプレート、日付形式を指定します。引き継ぎマーカーの初期値は `@carry` です。
6. コマンドパレットから **My Daily: 今日のデイリーノートを作成・開く** を実行します。左のカレンダー＋アイコンや、このコマンドに割り当てたホットキーも使えます。

標準のDaily notesとは別の作成コマンドです。引き継ぎを使う場合はMy Dailyのコマンドを使ってください。標準のDaily notesや別のプラグインで先に今日のノートを作成した場合、My Dailyはそのノートを開くだけです。

## 設定

| 設定 | 初期値 | 説明 |
| --- | --- | --- |
| 保存先フォルダ | `Daily` | Vaultからの相対パス。空欄ならVault直下 |
| テンプレート | `Templates/Daily.md` | `.md` は省略可能 |
| 日付形式 | `YYYY-MM-DD` | 年月日を含むMoment形式。`YYYY/MM/YYYY-MM-DD` のようなフォルダ分けも可能 |
| 引き継ぎマーカー | `@carry` | 引き継ぐ見出し名の先頭に付ける文字列。例: `## @carry 継続タスク` |

標準のDaily notesを併用する場合は、保存先と日付形式を同じにしてください。My Dailyの設定は独立して保存されます。

## 例

テンプレート:

```markdown
# {{date:YYYY-MM-DD}}

## 今日の予定
- [ ]

## @carry 継続タスク
- [ ]

## 日記
```

前回のノート（11月3日）:

```markdown
# 2026-11-03

## 今日の予定
- [x] 打ち合わせ

## 継続タスク
- [ ] 記事を書く
- [ ] 本を読む

## 日記
今日は打ち合わせがあった。
```

テンプレートの「継続タスク」にマーカーが付いているため、11月5日に作成するノートは次のようになります。11月4日のノートがなくても、直近の11月3日から引き継ぎます。既存の過去ノートの見出しにはマーカーがなくても使えます。

```markdown
# 2026-11-05

## 今日の予定
- [ ]

## @carry 継続タスク
- [ ] 記事を書く
- [ ] 本を読む

## 日記
```

## 引き継ぎのルール

- テンプレートの構成と見出しを使い、マーカー付きの見出しの本文を前回の本文で置き換えます。単なる追記ではありません。マーカーは作成後の見出しにも残ります。
- マーカーは見出し名の先頭に付け、空白で見出し名と区切ります。`## @carry 継続タスク` は対象、`## 継続タスク @carry` や `## @carryover 継続タスク` は対象外です。複数のセクションに付けられます。マーカーのないテンプレートはそのまま使います。
- 本文は次の同じ階層、または上位の見出しまでです。子見出し、完了済みタスク、リンクなどもそのまま引き継ぎます。
- 前回のノートは、保存先と日付形式に一致するファイルから、今日より前で最も新しい日付を選びます。更新日時は使いません。
- 前回のノートがなければ、テンプレートをそのまま使います。前回に指定の見出しがない場合も、その部分はテンプレートを使い、通知します。さらに古いノートまでは探しません。
- 前回の見出しの本文が空なら、空のまま引き継ぎます。
- 今日のノートが既にあれば開くだけです。前回のノートやテンプレートも変更しません。
- マーカーを除いた見出し名で照合します。大文字・小文字やMarkdown装飾も含めて一致させます。前回はマーカー付きの見出しを優先し、なければマーカーなしの同名見出しを使います。
- 引き継ぐ見出し名は一意にしてください。候補が複数ある場合や、親と子の見出しの両方にマーカーを付けた場合は、作成前にエラーを表示します。親のマーカーだけで子見出しも含まれます。
- `#` 形式と下線形式の見出しに対応します。コードフェンス、字下げコード、引用、YAMLフロントマター、HTMLコメント、Obsidianの `%%` コメント内の見出しは対象外です。HTMLブロック内など、複雑なMarkdown構造には対応していません。引き継ぐ見出しは通常の本文に置いてください。

テンプレートでは `{{title}}`、`{{date}}`、`{{time}}`、`{{date:YYYY-MM-DD}}` などを使えます。日付の既定形式は `YYYY-MM-DD`、時刻は `HH:mm` です。これらはMy Dailyの固定の既定値で、標準Templatesの設定とは連動しません。前回から引き継いだ内容の変数は再展開しません。Templaterのスクリプトは実行しません。

## 開発と確認

Node.js 22.18以降を使用します。

```sh
npm ci
npm run check
```

`npm run check` は型チェック、`main.js` のビルド、セクションの合成・日付の選択・Obsidian APIを模したノート作成のテストを実行します。`npm run dev` で変更を監視してビルドできます。

実際のObsidianで確認する場合は、上記手順でプラグインを有効にし、サンプルテンプレートと過去の日付のノートでコマンドを実行してください。このプロジェクトの自動テストはObsidian本体の画面操作を含みません。
